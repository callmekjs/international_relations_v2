# 에러노트

## 2026-09-15: 특수 점 문자가 파일에 옮겨 적는 중에 바뀌거나 사라짐

**증상:** 가운뎃점 변형 문자 시험 1개 실패. normalize("한미")가 "한·미"가 되기를 기대하는데, 예상과 달라 보이는 시험이 됨

**원인:** 계획서 코드에 특수문자(U+0387 그리스 문자, 비공개 영역 U+F09E, U+00A0 띄어쓰기 없는 공백 등)가 글자 그대로 들어 있었음. 파일로 옮겨 적는 과정에서 유니코드 정규화로 U+0387이 U+00B7(가운뎃점)로 바뀌고 U+F09E가 사라짐. 그 상태로 시험이 실패한 채 커밋까지 됨.

**해결:** 특수문자를 모두 \uXXXX 이스케이프 표기법으로 적고 charcheck.py로 코드 번호를 확인. 시험이 모두 통과하면 그때 커밋. 실패한 두 커밋(3c0f148, 95dd929)은 통과하는 커밋 하나(ba637ac)로 합침.

**배운 점:** 눈에 안 보이거나 비슷하게 생긴 특수문자는 소스에 글자 그대로 쓰지 말고 \uXXXX 이스케이프로 적는다. 시험이 실패하면 커밋하지 않고 먼저 원인을 확인하고 해결한다.

## 2026-09-15: 기록(커밋) 서명에 다른 AI 모델 이름이 적힘

**증상:** 작업 2의 커밋 마지막 줄이 정해진 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`가 아니라 `Claude Haiku 4.5`로 적혀 검토에서 지적됨

**원인:** 코드를 만든 AI가 서명 줄을 자기 모델 이름으로 바꿔 적음. 보고서에는 서명이 맞다고 잘못 적음

**해결:** 코드는 그대로 두고 커밋 메시지만 정해진 서명으로 고침(f4db3a2 → 86bb758). 이후 작업마다 "서명 줄은 모델과 상관없이 그대로"라고 알려 줌

**배운 점:** 정해진 문구는 작업을 맡길 때 "바꾸지 말 것"을 분명히 적고, 커밋 뒤 `git log -1 --format=%B`로 직접 확인한다
