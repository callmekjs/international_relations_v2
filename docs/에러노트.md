# 에러노트

## 2026-09-15: 특수 점 문자가 파일에 옮겨 적는 중에 바뀌거나 사라짐

**증상:** 가운뎃점 변형 문자 시험 1개 실패. normalize("한미")가 "한·미"가 되기를 기대하는데, 예상과 달라 보이는 시험이 됨

**원인:** 계획서 코드에 특수문자(U+0387 그리스 문자, 비공개 영역 U+F09E, U+00A0 띄어쓰기 없는 공백 등)가 글자 그대로 들어 있었음. 파일로 옮겨 적는 과정에서 유니코드 정규화로 U+0387이 U+00B7(가운뎃점)로 바뀌고 U+F09E가 사라짐. 그 상태로 시험이 실패한 채 커밋까지 됨.

**해결:** 특수문자를 모두 \uXXXX 이스케이프 표기법으로 적고 charcheck.py로 코드 번호를 확인. 시험이 모두 통과하면 그때 커밋. 실패한 두 커밋(3c0f148, 95dd929)은 통과하는 커밋 하나(ba637ac)로 합침.

**배운 점:** 눈에 안 보이거나 비슷하게 생긴 특수문자는 소스에 글자 그대로 쓰지 말고 \uXXXX 이스케이프로 적는다. 시험이 실패하면 커밋하지 않고 먼저 원인을 확인하고 해결한다.

## 2026-09-15: 기록(커밋) 서명에 다른 AI 모델 이름이 적힘

**증상:** 작업 2의 커밋 마지막 줄이 정해진 `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`가 아니라 `Claude Haiku 4.5`로 적혀 검토에서 지적됨

**원인:** 코드를 만든 AI가 서명 줄을 자기 모델 이름으로 바꿔 적음. 보고서에는 서명이 맞다고 잘못 적음

**해결:** 코드는 그대로 두고 커밋 메시지만 정해진 서명으로 고침(f4db3a2 → 86bb758). 이후 작업마다 "서명 줄은 모델과 상관없이 그대로"라고 알려 줌

**배운 점:** 정해진 문구는 작업을 맡길 때 "바꾸지 말 것"을 분명히 적고, 커밋 뒤 `git log -1 --format=%B`로 직접 확인한다

## 2026-09-15: 정답지 g02는 맞게 답해도 늘 불합격

**증상:** 검토에서 지적됨. g02(2021년 12월 한·호주 정상회담 도시, 정답 "캔버라")는 조수가 정직하게 답하고 정답 쪽을 인용해도 채점에서 "정답 쪽을 확인된 근거로 인용하지 않음"으로 떨어짐. 정답지 시험은 사실 문항 12개 중 많아야 11개만 합격할 수 있었음

**원인:** 합격하려면 정답 쪽 인용이 "확인됨"이어야 하고, 인용 구절은 띄어쓰기·문장부호를 빼고 12자 이상이어야 함. 그런데 정답 쪽 2021-p139R은 연표(일지) 표이고, 캔버라가 나오는 칸은 "한·호주 정상회담 (캔버라)" 한 줄, 10자뿐이라 "문단만 확인"까지만 됨. 2021년치에서 캔버라가 나오는 다른 쪽(2021-p064R)은 1989년 APEC 출발 이야기라 이 회담의 근거가 아님. 계획서의 채점 규칙과 정답지가 서로 맞지 않았음(계획서 문제)

**해결:** 채점 규칙은 그대로 두고 g02 문항을 바꿈. 계획 1 찾기 시험 질문 v18에서 골라 "34년 만에 방한한 카리브 나라 외교장관은 어느 나라에서 왔어?", 정답 "바하마", 정답 쪽 2022-p055L(131자 문단에 그대로 있음). 2022년치 문항이 하나도 없던 것도 채워짐. 사실 문항마다 정답 쪽에 "사실이 들어 있고 확인됨이 나올 수 있는 문단"이 하나 이상 있는지 보는 시험을 새로 넣음. 이 시험은 옛 g02에서 실패하고 지금은 통과함

**배운 점:** 정답지를 만들 때 "사실이 정답 쪽 글자에 있는가"만 보면 부족하다. 채점 규칙 그대로(쪽을 읽고, 인용해서, 확인됨이 나오는지) 한 번 돌려 봐야 한다. 표 칸처럼 짧은 글에만 있는 사실은 정답으로 삼지 않는다

## 2026-09-15: 줄 끝 문자 차이로 시험 파일 끼워 넣기가 멈춤

**증상:** 계획서 코드 조각을 tests/test_halves.py에 끼워 넣는 스크립트가 "파일에 CRLF가 있다"며 멈춤. Git Bash의 grep으로 볼 때는 줄 끝이 LF로만 보였음

**원인:** 이 컴퓨터는 git 설정(core.autocrlf=true) 때문에 파일을 꺼낼 때 줄 끝을 CRLF(Windows 방식)로 바꿔 둠. 계획서 조각은 LF라서 글자 비교가 맞지 않았음. grep은 CR 문자를 보여 주지 않았음

**해결:** 스크립트가 읽을 때 CRLF를 LF로 바꿔 끼워 넣고, 쓸 때는 원래 줄 끝으로 되돌리게 함. git에는 LF로 저장되고, 바꾼 줄만 차이로 보임 (79ffb5f)

**배운 점:** 줄 끝 방식은 grep이 아니라 `git ls-files --eol`로 확인한다. 파일을 고치는 스크립트는 CRLF 파일도 다룰 수 있게 만든다

## 2026-09-15: 문장부호가 많은 짧은 구절이 "확인됨"을 받음

**증상:** 날짜 "(2023.4.26.)"처럼 글자와 숫자는 7개뿐인 구절이 "구절이 짧음"으로 낮춰지지 않고 "확인됨"을 받음

**원인:** 규칙은 "띄어쓰기와 문장부호를 빼고 12자 이상"인데, 계획서 코드는 괄호, 점, 쉼표까지 글자 수에 넣었음. 글로 쓴 규칙과 코드가 서로 달랐음

**해결:** 글자와 숫자만 세도록 고침. 문장부호가 섞인 구절로 11자는 짧음, 12자는 확인됨이 나오는지 경계 시험을 넣음 (14bc718)

**배운 점:** 규칙을 글과 코드로 함께 적었으면, 두 해석이 갈리는 입력(문장부호가 많은 날짜와 숫자)으로 경계를 시험한다

## 2026-09-15: 음수에서 마이너스 부호를 뺀 인용이 "확인됨"을 받음

**증상:** 원문이 "-1.0%의 성장률을 기록하였다"(마이너스 성장)인데, 부호를 뺀 "1.0%의 성장률을 기록하였다"를 인용해도 "확인됨"이 나오고 보여 주는 근거에서도 부호가 사라짐. 뜻이 반대가 됨

**원인:** "긴 숫자의 중간부터 인용하면 안 된다"는 검사가 구절 바로 앞의 숫자, 소수점, 쉼표만 보고 마이너스 부호는 보지 않았음

**해결:** 구절 바로 앞 글자가 마이너스 부호면 인용을 거절하도록 고침. 부호까지 넣은 인용은 그대로 확인됨. 긴 줄표와 짧은 하이픈 둘 다 시험함 (14bc718)

**배운 점:** 숫자 가장자리를 지키는 규칙은 숫자의 값을 바꾸는 모든 글자(부호와 구분 기호)를 다뤄야 한다. 비교 키를 만드는 코드와 같은 부호 판단을 함께 쓴다

## 2026-09-15: 정답지 g07의 반올림 숫자 오타

**해결:** "2,276만"으로 고침. 모든 정답 표현이 코퍼스 어딘가에 실제로 있는지 보는 시험을 넣음 (2b1d0d4)

## 2026-09-15: 정답지 g12 질문에 맞는 답이 여러 개

**증상:** g12는 "2021년 한·호주 정상회담"이 열린 도시를 묻고 캔버라만 정답으로 받음. 콘월이나 로마라고 맞게 답해도 불합격이 될 수 있었음

**원인:** 2021년에 한·호주 정상회담이 세 번(6월 콘월, 10월 로마, 12월 캔버라) 열렸음. 계획서 질문에 "12월"이 빠져 답이 하나로 정해지지 않았음. 기존 시험은 정답이 정답 쪽에 있는지만 봄

**해결:** 질문에 "12월"을 넣음(g02 옛 질문과 같은 표현). 2021년 한·호주 정상회담을 묻는 질문에 12월이 없으면 실패하는 시험을 넣음 (147dad0)

**배운 점:** 사건을 연도로만 가리키면 그해 연표에서 같은 사건이 여러 번 있었는지 찾아본다. 여러 번이면 달이나 장소를 넣어 답이 하나가 되게 한다

## 2026-09-15: 요금이 나간 뒤 뜻밖의 오류 하나로 실행이 멈추고 기록이 사라질 수 있었음

**증상:** 최종 검토와 추가 점검에서 드물지만 실제로 생길 수 있는 문제들이 나옴. 모델이 가격표에 없는 이름을 돌려주면 요금 계산에서 멈춰, 이미 돈을 낸 요청의 기록이 남지 않음. 열쇠나 코퍼스가 없으면 안내 대신 오류 화면이 뜸. 연도 "20x3", 다른 문자의 숫자, 깨진 스트림 데이터, 이상한 대기 시간(Retry-After) 값에도 멈추거나 잘못 동작함. 정답지 시험은 한 문항이 멈추면 전체가 멈춤. 터미널 명령은 안내를 두 번 찍음

**원인:** 계획서 코드가 예상한 오류(LLMError)만 잡고 나머지 예외는 그대로 위로 올려 보냈음. 밖에서 들어오는 값(모델 응답, 사람 입력, .env 파일)의 모양 검사도 느슨했음

**해결:** 요금은 돌려받은 모델 이름, 요청한 모델 이름, 0원 순서로 계산하고 쓴 이름을 price_model에 남김. 루프와 run()은 뜻밖의 예외에도 안내(열쇠나 코퍼스가 없으면 "설정 문제", 그 밖에는 "알 수 없는 문제")와 함께 결과를 돌려주고, 그때까지의 요청 기록과 error 칸("예외 종류: 메시지")을 남김. 연도와 도구 숫자는 ASCII 숫자만 받음. 요금 한도 코드는 어느 경로로 와도 "사용량이 다 찼어요" 안내, 408과 409 및 출력 전 스트림 오류는 다시 시도. 터미널 명령과 정답지 시험도 오류에 멈추지 않게 함. 고칠 곳마다 먼저 실패하는 시험을 만들고, 고친 뒤 통과를 확인함 (03b7b57)

**배운 점:** 돈이 드는 단계 뒤의 코드는 예상 못 한 예외가 나도 기록을 남기고 끝나게 만든다. 모델 응답, 사람 입력, 파일처럼 밖에서 오는 값은 모양을 확인한 뒤 쓴다
